# Phase 14: Technical Evidence & Mechanism Record

## Purpose
This document strictly captures experimentally demonstrated technical mechanisms of the Verification Engine. It does NOT assert guaranteed patentability, but rather records engineering observations for subsequent legal review.

## 1. Deterministic Verification Manifest
**Mechanism:** The system produces a canonical representation of a verification event. 
- Input variables (matched fragments, control-flow relationships) and version constants are fed into a recursive, key-sorted stringifier.
- **Measured Effect:** Hash invariance. Testing confirms that changing property insertion order in the JS runtime (e.g. `{'a':1,'b':2}` vs `{'b':2,'a':1}`) consistently produces the exact same `evidenceDigest` (SHA-256).

## 2. Receipt Salting and Replay Protection
**Mechanism:** The `VerificationReceipt` decouples non-deterministic execution metrics (e.g., latency, worker thread ID, current timestamp) from the deterministic evidence manifest.
- A unique `verificationId` is generated by hashing the `evidenceDigest` along with the current timestamp and a 16-byte random salt.
- **Measured Effect:** Replaying the same exact inputs produces identical Evidence Digests, but mathematically distinct Receipt IDs, preventing replay collisions in the audit log while guaranteeing proof of identically matched logic.

## 3. Cryptographic Tamper Detection
**Mechanism:** The `evidenceDigest` binds the semantic match details to the algorithm versions used.
- Any bitwise modification to the JSON (such as adding an injected "frag4-fake") mathematically alters the root hash.
- **Measured Effect:** Our tamper test strictly validates that injecting malicious fragments invalidates the evidence signature instantly.

## Limitations
- Serialization logic recursively sorts keys, which introduces slight CPU overhead compared to native V8 `JSON.stringify`.
- The current implementation of the append-only Audit Log uses local file appending, which is susceptible to OS-level tampering. A distributed ledger or secure enclave would be needed for absolute immutability.
