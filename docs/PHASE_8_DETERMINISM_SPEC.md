# Phase 8: Determinism Specification

To guarantee that $P_1 = P_2 \implies \text{Fingerprint}(P_1) == \text{Fingerprint}(P_2)$, the canonicalization and hashing pipeline enforces strict deterministic constraints.

## 1. AST Serialization Determinism
- **JSON Stringification**: The engine relies on the V8 engine's guarantee that `JSON.stringify` serializes object keys in creation order. However, since parsers may alter AST node key ordering between versions (e.g., Acorn v8 vs v9), the node is deeply sorted alphabetically by key prior to serialization.
- **Identifier Masking**: All AST nodes of type `Identifier` have their `name` property irreversibly overwritten with a static constant (e.g., `""` or `<ID>`).
- **Literal Masking**: All AST nodes of type `Literal` have their `value` and `raw` properties overwritten with static constants to ensure that `const a = 1;` and `const a = 2;` hash identically, focusing purely on graph topology.

## 2. Multiset Sorting Determinism
- Graph edge accumulation is purely commutative. Therefore, the list of incoming hashes $\{H(u_1), H(u_2), ...\}$ is sorted using **Lexicographical UTF-16** sorting prior to concatenation.
- The final program fingerprint is generated by sorting the array of all $K$-iterated Basic Block hashes lexicographically.

## 3. Scope and Sequence Numbering
- **Explicit Erasure**: CIPE explicitly *does not* use scope numbering or sequence numbering (e.g. tracking that a variable was declared in Scope 3). Doing so breaks positional independence if a function is moved to a new file depth. All positional mapping is abandoned in favor of topological mapping.

## 4. Invariant Boundaries
For explicitly supported transformations $T(P)$ (such as renaming variables or converting syntactically equivalent structures), the engine guarantees:
$C(P) = C(T(P))$

Where a transformation is unsupported (e.g. semantic algorithm swapping, or `for` loops converted to recursive functions), $C(P) \neq C(T(P))$.
