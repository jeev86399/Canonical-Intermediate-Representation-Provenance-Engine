# Phase 11: Provenance Fragment Index Design

## 1. Executive Summary

The `@cipe/provenance-index` package provides high-throughput indexing and candidate retrieval for structural code fragments generated by the CIPE pipeline. It maps canonical Weisfeiler-Lehman Weisfeiler-Lehman Continuous Directed Hypergraph (WLCDH) fragment hashes to their occurrence metadata across repositories, commits, and file paths.

```
[ WLCDH Fragments ] ──> [ Input Validation ] ──> [ In-Memory Map<Fingerprint, Metadata[]> ] ──> [ O(1) Candidate Retrieval ]
```

## 2. Architecture & Data Structures

The core storage model is built on an in-memory hash map (`Map<string, Array<FragmentRecord>>`):
- **Key**: 64-character SHA-256 hexadecimal string representing the structural fragment fingerprint.
- **Value**: Array of metadata records capturing provenance origin (`repositoryId`, `commitHash`, `filePath`, `canonicalVersion`, `algorithmVersion`, `timestamp`).

Lookup complexity is strictly $O(1)$ per fragment, enabling microsecond-scale candidate identification across millions of indexed fragments prior to expensive pairwise WLCDH verification.

## 3. Public API Specification

| Method | Signature | Description |
| :--- | :--- | :--- |
| `addFragment` | `(fingerprint: string, metadata: object) => boolean` | Validates and indexes a single fragment occurrence. |
| `queryFragment` | `(fingerprint: string) => Array<object>` | Returns all metadata records associated with a fingerprint. |
| `queryBatch` | `(fingerprints: string[]) => Map<string, Array<object>>` | Executes multi-fragment candidate retrieval in a single pass. |
| `getStats` | `() => object` | Returns fragment count, total record count, and memory overhead metrics. |
| `exportIndex` | `() => string` | Serializes index state to a structured JSON payload. |
| `importIndex` | `(serialized: string) => void` | Validates and restores serialized index state. |
| `identifyCommonFragments` | `(threshold: number) => Array<string>` | Returns fragments occurring above a frequency threshold (e.g., idiom detection). |
| `baselineSearch` | `(fingerprints: string[]) => object` | Executes linear scan baseline search for benchmark validation. |
| `clear` | `() => void` | Resets the in-memory index state. |

## 4. Input Validation & Defensive Guardrails

To prevent denial-of-service and state corruption attacks in multi-tenant environments, `@cipe/provenance-index` enforces strict boundaries:

1. **Fingerprint Format Validation**:
   - Must match strictly `/^[a-f0-9]{64}$/i`.
   - Rejects non-hex, truncated, malformed, or prototype pollution keys (`__proto__`, `constructor`).

2. **Metadata Payload Size Limit**:
   - Maximum serialization limit of 10 KB per metadata payload.
   - Prevents memory exhaustion attacks via oversized JSON objects.

3. **Flood Protection / Record Caps**:
   - Caps maximum records per single fragment at 500 entries.
   - Prevents hot-spot degradation caused by ubiquitous boilerplate idioms.

4. **Path Traversal & Injection Sanitization**:
   - Path normalization rejects directory traversal sequences (e.g., `../`, `..\\`).
   - Rejects shell metacharacters in `repositoryId` and `commitHash` fields.

## 5. Implementation Characteristics

The package is packaged as a CommonJS module (`packages/provenance-index/index.js`) with zero external runtime dependencies, ensuring high portability and integration with downstream CI/CD tools and verification microservices.
