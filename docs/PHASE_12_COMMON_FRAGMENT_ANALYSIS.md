# Phase 12: Common-Fragment Suppression Analysis

## Objective
To eliminate False Positives (FP) generated by ubiquitous programming patterns (e.g., standard boilerplate, auto-generated stubs, trivial getter/setters, or highly standardized implementations like basic loops).

## Methodology
The `CommonFragmentSuppressor` tracks the global frequency of generated cryptographic fingerprints across a large corpus of repositories. It applies an Inverse Document Frequency (IDF) weighting model.

### Frequency Weighting Model
A fragment's evidentiary weight $W$ is calculated as:
$$W = \max\left(0, \min\left(1.0, \frac{\ln(N / C)}{\ln(N + 1)}\right)\right)$$

Where:
- $N$ = Total number of fragments analyzed in the corpus.
- $C$ = Count of occurrences for the specific fragment hash.

### Categorization
Fragments appearing above an absolute threshold (e.g., $> 5\%$ frequency in a diverse corpus) are strictly classified as `COMMON_BOILERPLATE`.

When a verification query executes, the engine partitions matches into two sets:
1. **Rare Matches**: High evidentiary value.
2. **Common Matches**: Acknowledged in the evidence graph as `COMMON_BOILERPLATE`, but excluded from calculating `EXACT_MATCH` or `STRUCTURAL_MATCH`.

## Technical Observations
By isolating and suppressing common fragments, CIPE successfully distinguishes between independently written but structurally identical utility functions, and genuine partial plagiarism of complex algorithms.
